# sync 规则

默认策略见 `fixtures/policy.json`。

## 输入

- `fixtures/take.wav` 是独立录音机的 48 kHz stereo 文件。标签采样率是 48000，但实际录制时钟相对摄像机偏快大约 120 ppm，而且响板（clap）不在文件开头。
- `fixtures/video-clock.json` 给出每正帧的采集时间 `pts_seconds`（摄像机时间轴，秒）、`fps`（25）和 `clap_frame`（响板所在的视频帧号）。摄像机时间轴本身也可以有轻微的非均匀间隔，不能假设帧间隔恒为 1/25。

## 对齐

- 先在音频里定位响板：在策略 `clap_search_s`（默认前 3 秒）里找绝对峰值。该峰值应对准 `clap_frame` 的视频时间 `pts_seconds[clap_frame]`。允许的定位误差在报告里以 `clap_error_ms` 给出，sync 之后应小于 `max_clap_error_ms`（默认 2）。
- 漂移估计：以响板为 0 点，用音频样本索引（按标签 48000 Hz）和视频 `pts_seconds` 做线性拟合，得到 `drift_ppm`（正值表示录音机偏快）。公开夹具大约是 +120 ppm，允许报告误差 ±10 ppm。
- 然后做异步重采样，把音频锁到视频时钟：输出音频的第 n 个采样对应视频时间 `t = pts_seconds[0] + n / output_rate`，从输入中按估计的时钟映射取点。输出采样率是 `output_rate`（默认 48000）。
- 重采样必须是加窗 sinc，窗口至少 24 点（每侧 12 个过零），窗函数用 Hann 或 Blackman。禁止只用线性插值或最近邻交差。
- 输出时长覆盖从第一帧到最后一帧的视频时间跨度（含两端），不足的输入写 0。响板之后音画不得再慢慢漂：用输出音频的响板峰值和末尾 0.5 秒内一个标记音（见下）核对，末尾对齐误差不得超过 `max_tail_error_ms`（默认 2）。

## 标记音

- 输入在响板处有一个短脉冲。另外在文件后部还有第二个脉冲，对应视频里 `tail_mark_frame`（写在 clock 文件中，若缺失则不考核尾点）。这两个脉冲都要在输出里出现在对应视频时间上。

## 退出码

- 成功写出锁定后的 WAV 和完整报告：退出 0，`decision` 为 `ok`。
- 找不到响板或漂移估计失败（可读脉冲少于 1 个）：退出 1，`decision` 为 `reject`。
- 文件无法解析：退出 2。
